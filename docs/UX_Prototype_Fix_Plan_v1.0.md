## 0. 전제

### 0-1. 단계별 로드맵과 검증 질문

| 단계 | 검증 질문 | 실패 시 손실 |
|---|---|---|
| **지금 — UX Prototype** | 이 흐름이 말이 되는가? 제안이 이해되는가? | 잘못된 구조 위에 UI를 입힘 |
| 다음 — UI 입히기 | 전문적이고 갖고 싶어 보이는가? | 내부 반응이 안 나옴 |

**이번 단계의 실제 리스크는 "안 예쁘다"가 아니라, 리뷰어가 UX가 아닌 것에 반응해서 UX 판단을 받지 못하는 것이다.**
따라서 모든 항목의 판정 기준은 완성도가 아니라 다음 한 줄이다.

> **이것이 내부 공유에서 리뷰어의 판단을 오염시키는가?**

### 0-2. 이번 단계 범위 밖 (의도된 제외)

실제 데이터 입력·저장 기능은 범위에서 제외됨. 따라서 아래는 **결함이 아니다.**

- `localStorage` 미사용 / 새로고침 시 상태 소실
- 닉네임 + 4자리 PIN 재진입이 하드코딩된 샘플 카드를 반환하는 것
- 카드 저장 / 공유 / 가격 확인 / 구매처 확인이 토스트만 띄우는 것

단, **"무엇이 일어날지"가 화면에 없으면 반응을 물어볼 수 없다.** → §4 참조.

## 2. A-1. 명제가 화면에 보이게 한다 `최우선`

### 문제

`renderRecommendation()`은 `state.scenario`(LONG/SPEED/REPLACE/RACE 4개) 하나로 결과를 결정한다. 우선순위(`gearPriority`)는 칩과 요약 문장에만 등장하고 **후보를 바꾸지 않는다.** 주간거리·경력·현재 신발도 마찬가지다.

→ **5문항을 풀든 안 풀든, 반발감을 고르든 안정감을 고르든 나오는 3개가 같다.** 서비스 명제("나를 이해하면, 장비 선택이 달라진다")가 화면에서 한 번도 시연되지 않는다. 리뷰어는 "괜찮은데 그냥 신발 추천 사이트 같다"고 답할 것이다.

### 설계 제약 (D-01)

> Runner Type은 Identity Layer다. **Recommendation Score에 절대 투입하지 않는다.**

따라서 **Runner Type으로 후보를 바꾸면 안 된다.** 대신 역할을 나눈다.

| 무엇이 | 무엇을 바꾸는가 |
|---|---|
| **판정 변수** (목적 · 우선순위 · 주간거리 · 현재 신발) | **후보 선정과 정렬** |
| **Runner Type** | **말 거는 방식** (리드 문장, 코치 첫 마디) — 후보는 건드리지 않음 |

이 분리는 D-01을 지키면서도 "내가 답한 게 결과를 바꿨다"는 체감을 만든다.

### 작업 항목

| # | 항목 | 내용 |
|---|---|---|
| **A-1-1** | **우선순위 → 실제 정렬** | `gearPriority`로 후보 3개를 재정렬한다. `productAttrs` 실측값 사용: 편안함 → `cushionScore` ↓ / 안정감 → `stabilityScore` ↓ / 반발감 → `responsivenessScore` ↓ / 가벼움 → `weightG` ↑. `잘 모르겠어요`면 기본 순서 유지 |
| **A-1-2** | **인과 문장 노출** | 추천 상단에 한 줄: *"반발감을 가장 중요하게 고르셔서, EVO SL을 먼저 뒀어요."* — **이 한 줄이 시연의 핵심이다.** 정렬만 바뀌고 이유를 말하지 않으면 아무도 눈치채지 못한다 |
| **A-1-3** | **되돌아오는 루프** | `추천 기준 수정`으로 우선순위를 바꾸면 순서가 눈앞에서 바뀌도록. 리뷰어에게 가장 강력한 데모 |
| **A-1-4** | **스펙 한 줄 + 정가** | 후보마다 `무게 220g · 드롭 6.7mm · 플레이트 없음 · 209,000원`. `seed/products.v0.2.json`에서 그대로. **전문성 인상을 가장 싸게 올리는 항목** |
| **A-1-5** | **Runner Type 리드 문장** | `WHY FOR YOU` 앞에 타입별 한 줄. 예: PACE → *"1초를 줄이는 재미가 커지는 지금이라면,"* / ROUTINE → *"꾸준한 흐름을 끊지 않는 게 우선이라면,"*. **후보 순서에는 관여하지 않는다** |
| **A-1-6** | **후보를 Eligible 29개로 교체** | `Zoom Fly 6` / `Alphafly 3` 제외 (C-5). 시나리오별 대체: RACE는 `Adizero Adios Pro 4` / `FuelCell SuperComp Elite v5` / `METASPEED SKY TOKYO` / `Endorphin Pro 5` / `Fast-R NITRO Elite 3` 중 선정. SPEED는 TEMPO 7종 중 선정 |

> **주의**: 추천 엔진을 만드는 작업이 아니다. 정렬 규칙 하나와 문장 매핑 테이블 하나면 된다. 제품 풀이 시나리오당 고정이어도 이번 단계 목적은 달성된다.

기존 5문항의 **문구는 한 글자도 바꾸지 않았다.** 선택지에 붙어 있던 자체 점수표만 규칙 필드로 교체했다.

### 구조 변경 2건

1. **대회 확정 여부 → 관심 거리 질문으로 교체.**
   기존 가드레일("참가 확정된 대회가 있나요?" 예/아니요)은 폐지된 RACE 타입을 막기 위한 장치였다. 새 체계에는 RACE 타입이 없다. 대신 규칙이 실제로 필요로 하는 `interestDistance`(`longTarget` 가점 · `RACE_READY` Modifier)를 같은 자리에서 받는다. **A-2-3의 중복 질문(코치 단계 거리 재질문)도 함께 해소됐다.**

2. **2단계 판정 — 이게 E-3을 살린다.**
   - 5문항 직후: `purpose`/`trend`/`goal`/`interestDistance`로 **잠정 판정** → cardLite
